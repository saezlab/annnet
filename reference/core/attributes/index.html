    Attributes

    The attribute API from annnet.core._attribute_api and the row selections from annnet.core._select. Direct imports from underscore modules follow the internal API policy; the public names are exported as annnet.Attrs, annnet.RowSelection and annnet.Schema.

    Attrs is what G.attrs gives back: the eight attribute addresses — nodes, edges, slices, aspects, layers, edge_slices, node_layers, elementary_layers — read and written the same way. A read (nodes, table, row, rows) returns a detached copy; a write is a named call (update, replace, delete); select is a live query and from_frame a fixed selection made from the rows of a table you filtered yourself. The contract is stated in the API contract, section 3; the reading workflow in Reading the graph; the storage in Internal representation.

    annnet.core._attribute_api.Attrs

    Every attribute of a graph, at eight addresses (G.attrs).

    See the module docstring for the shape. The reader protocol the selection machinery uses is the set of underscored methods _domain, _row, _rows_where, _key, _selection_owner and _root_reader.

    schema 
    schema(address, *, derived=False)

    Report what an address is keyed by and what it holds, cheaply.

    select 
    select(address, conditions=None, /, **keywords)

    Select the rows of one address that satisfy every condition.

    The conditions are the ones G.N.select takes, over the address's key columns, its stored fields, and — for the layer-keyed addresses — the declared aspects, compared by their order when ordered. Keys are kept as the address keys them; see :meth:RowSelection.project.

    replace 
    replace(address, table)

    Replace the attributes of a whole address with the rows of a table.

    Parameters:

    Name Type Description Default
    address str

    One of :data:ADDRESSES.

    		 required
    table DataFrame - like

    A table in any supported backend with the address's key columns and one column per attribute. Null cells mean "no such attribute".

    		 required
    Notes

    A key the table omits loses its attributes and keeps its existence: the nodes, edges, slices and layers themselves are never added or removed by a table. The table is validated whole before anything changes, and the old attributes are restored if the write fails. Use :meth:update to change some fields of some rows.

    Raises:

    Type Description
    ValueError

    For a missing key column, a null or duplicate key or a reserved field.
    KeyError

    For a key the address does not hold.

    from_frame 
    from_frame(address, frame)

    Select the rows of a frame, by the keys it names.

    Read a table, filter it with the dataframe library it came in, and pass what is left here to get a selection of the graph's own keys::

    table = G.attrs.table('nodes')
kept = table.filter(pl.col('score') > 0.5)
chosen = G.attrs.from_frame('nodes', kept)

    Parameters:

    Name Type Description Default
    address str

    One of :data:ADDRESSES.

    		 required
    frame DataFrame - like

    Any supported backend. Only the address's key columns are read.

    		 required

    Returns:

    Type Description
    RowSelection

    A selection of exactly those keys, in the address's own order and without repeats. It is fixed: it is the identities the frame named, not the condition that produced the frame, so a key added later is not picked up, and a key that is removed and added again is the same key. An empty frame gives an empty selection.

    Raises:

    Type Description
    ValueError

    For a missing key column or a null key.
    KeyError

    For a key the address does not hold (or, on a view, one outside it).

    audit 
    audit()

    Report attribute rows whose structural keys no longer exist.

    The generic tables are derived from slot-indexed columns, so they can hold no extra row and miss none; what an audit still finds is a contextual row naming a slice, edge, node, layer or placement the graph does not hold.

    annnet.core._select.RowSelection

    The rows of one attribute address that satisfy a query, keyed as the address keys them.

    Built by G.attrs.select / V.attrs.select. It keeps the full keys — a node-layer row keeps its (node_id, layer) — until :meth:project is called. It is live: .keys re-evaluates the query against the graph as it is now, each leaf inside the scope it was asked in. Two selections of the same address on the same graph combine with &, | and -; the result keeps the address's own order.

    Attributes

    keys property 
    keys

    The keys of the matching rows, in the address's own order.

    ids property 
    ids

    Alias of :attr:keys, so every selection answers .ids.

    Functions

    rows 
    rows()

    The matching rows as detached dictionaries, keyed by their keys.

    project 
    project(target)

    Project the selected rows onto one axis of their keys.

    node_layers rows project to nodes; edge_slices rows project to edges or slices. The projection is existential — an element is selected when at least one matching row names it — and it keeps the target axis's order with duplicates removed. It does not say "in every slice"; that is a reduction over the frame, not a selection.

    Returns:

    Type Description
    NodeSequence | EdgeSequence | SliceSelection

    A live selection of the target axis, in the scope of this selection.

    Predicates

    The one predicate language every select parses.

    annnet.core._predicate

    The one predicate engine every selection surface shares.

    G.N.select(score__gt=0.5), G.E.select(kind='hyper'), G.attrs.select('node_layers', score__gte=0.8) and G.layers.where(time__lte='12h') are four spellings of one question: which rows of this axis satisfy these conditions. They parse the conditions here, evaluate them here, and report a bad field, operator or value the same way.

    A condition is field=value (equality) or field__operator=value with one of :data:OPERATORS. A literal field whose own name contains __ wins over suffix parsing, and a positional mapping may use explicit (field, operator) keys where a keyword would be ambiguous.

    Null handling is one rule everywhere: a missing value — None or a float NaN — is excluded by every comparison, including ne and not_in, and selected only by an explicit field__isnull=True.

    An ordered aspect compares by its declared order, through order=; a categorical aspect refuses the four ordering operators. A numeric attribute compares numerically. Two values that cannot be compared raise, naming the field and the operator, rather than silently dropping the row.
